# SubExtractor 迭代计划

项目：离线桌面视频 → 双语字幕（en / fr / ja / ko）
原则：每个迭代都要有**可运行的产出**和**可验证的验收标准**；先跑通端到端，再逐环节提质量。

---

## 总览

| 迭代 | 目标 | 关键交付 | 依赖 |
|---|---|---|---|
| M0 | 项目骨架与环境 | 可运行 CLI 冒烟 | — |
| M1 | 抽音轨 + 源语 ASR | `name.orig.srt` | M0 |
| M2 | 翻译 + 双语输出 | `name.bilingual.<lang>.srt` | M1 |
| M3 | 断句与时间轴质量 | 语言参数表 + 合规输出 | M2 |
| M4 | 桌面 GUI | 全流程可视化操作 | M3 |
| M5 | 批处理与鲁棒性 | 目录批量 + 断点续跑 | M4 |
| M6 | 打包与可选扩展 | Windows 可执行包 | M4 / M5 |
| M7 | 质量评估与调优 | 评测报告 + 参数冻结 | M3 / M5 |

> 建议：M1–M3 纯 CLI/核心库驱动，先把正确性做对；GUI 放到 M4 之后，避免早期返工。

---

## M0 项目骨架与环境

**任务**
- 创建目录结构（见设计大纲 §6）、`pyproject.toml`、依赖锁定
- FFmpeg 探测（imageio-ffmpeg 内置二进制）
- 日志、配置加载、CLI 入口 `python -m subextractor`
- `models/` 目录约定与 `checksums.json` 骨架

**验收**
- `python -m subextractor --version` 正常输出
- `python -m subextractor doctor` 打印 FFmpeg / 模型目录 / 缺失模型状态

---

## M1 音轨抽取 + 源语 ASR（核心）

**任务**
- `media.py`：调用 FFmpeg 抽音轨 → 16k mono wav（临时文件清理）
- `asr.py`：封装 faster-whisper，支持模型档位、源语 auto/指定、词级时间戳开关
- `writer.py` 先实现单语 SRT 输出
- CLI：`subextract --input a.mp4 --src auto --format srt`

**验收**
- en / fr / ja / ko 各 1 段样本，产出时间轴正确的 `name.orig.srt`
- 自动检测语言与强制指定两种模式均可用
- 长音频（≥30min）不崩、有进度输出

---

## M2 翻译与双语输出

**任务**
- `translate.py`：`Translator` 抽象 + NLLB-200-600M(int8) 实现；Argos 作为轻量备选
- `writer.py`：双语 SRT（第 1 行源语、第 2 行译文）与译文单语 SRT
- 语言对校验：源语 == 目标语时跳过翻译并提示
- 批量翻译时按批合并以减少显存/耗时

**验收**
- en↔fr、en→ja、en→ko、ja→ko 等组合均可产出 `bilingual.<lang>.srt`
- 用 PotPlayer/VLC 外挂加载，双语显示正常、无乱码
- 断网环境下全流程可跑（模型已预置）

---

## M3 断句与时间轴质量

**任务**
- `segment.py`：按目标语言字符预算拆 cue；cue 时长上下限、去重叠、合并过短 cue
- `config/languages.yaml`：en/fr/ja/ko 四套参数（行长、行数、时长、CPS）
- ja/ko 专项规则：不在助词/助动词处断行；日文按文节
- `postcheck.py`：输出前校验 CPS/行长/重叠并输出报告

**验收**
- 长句不再溢出屏幕；单 cue ≤2 行且每行不超阈值
- ja/ko 抽样 30 条人工评审，断行位置合理（通过率 ≥90%）
- 相邻 cue 零重叠、无 <0.8s 的碎片 cue

---

## M4 桌面 GUI（PySide6）

**任务**
- 拖拽/选择文件、源语与目标语下拉、ASR 模型档位、是否输出 ASS
- 进度条 + 分阶段状态（抽音轨/识别/翻译/写盘）、可取消
- 结果预览（字幕表格）、打开输出目录、错误可读提示
- 配置持久化（记住上次语言与模型选择）

**验收**
- 不碰命令行即可完成"视频 → 双语字幕"全流程
- 取消能中断且清理临时文件；典型错误有中文提示

---

## M5 批处理与鲁棒性

**任务**
- 目录批处理、任务队列、并发度控制
- 断点续跑：中间产物缓存（音轨/源语段 JSON），重跑跳过已完成阶段
- 异常恢复与失败清单输出
- 长视频按 VAD 静音切分

**验收**
- 20 个文件批量跑通，失败可单独重跑
- 中途 kill 进程后重启，可从中断阶段续跑

---

## M6 打包与可选扩展

**任务**
- PyInstaller 打包 Windows（模型外置，仅打包运行时）
- 首次启动向导：检测模型、给出放置/校验指引
- 可选 1：ASS 输出（东亚/拉丁分别样式）
- 可选 2：术语表（术语替换，不改写引擎）
- 可选 3：画面硬字幕 OCR 提取（借鉴 video-subtitle-extractor 思路）

**验收**
- 干净机器上，模型预置后双击即可用
- 安装包不含模型权重（体积可控）

---

## M7 质量评估与调优

**任务**
- 建立小评测集（en/fr/ja/ko 各若干，含术语/长句/口音）
- 指标：ASR 字错率、断句合规率、双语可读性人工评分
- 调参：断句阈值、模型档位、翻译批次；固化到 `languages.yaml`
- 输出评测报告，冻结 v0.1 参数

**验收**
- 有可复现的评测脚本与报告
- 四语在评测集上达到预设阈值，参数写入版本

---

## 里程碑依赖与交付节奏

```
M0 → M1 → M2 → M3 → M4 → M5 → M6
                   └──────────→ M7（评测可并行于 M5/M6）
```

- **端到端最早可用点：M2 结束**（此时已能产双语 SRT，可先用起来）
- **面向自用可用点：M4 结束**（GUI 就绪）
- **可分发点：M6 结束**

## 风险与应对（迭代内关注）

| 风险 | 出现迭代 | 应对 |
|---|---|---|
| ja/ko 断句质量不达标 | M3 | 专项规则 + 评测集回归，必要时引入语言模型辅助切分 |
| NLLB 显存占用高 / CPU 太慢 | M2 | int8、分批、允许切换 Argos 轻量档 |
| 模型缺失导致首次体验差 | M0/M6 | 首次向导 + 校验清单 + 明确指引 |
| 打包体积过大 | M6 | 模型外置，不进包 |
| 首版范围蔓延 | 全程 | 严守非目标（无实时、无配音、无云端） |
